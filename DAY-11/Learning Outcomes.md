## 🎯 Learning Outcomes

- Understand why Salesforce applications need to integrate with external systems.

- Explain the role of APIs and how independent applications communicate through an agreed API contract.

- Understand REST APIs and confidently use HTTP methods such as:
  - GET
  - POST
  - PUT
  - PATCH
  - DELETE

- Understand API request and response structures, including:
  - Endpoints
  - Headers
  - Request Body
  - Response Body
  - HTTP Status Codes

- Read and work with JSON data exchanged between Salesforce and external systems.

- Understand how Apex HTTP callouts communicate with REST APIs.

- Design a clean integration flow using:
  Trigger → Service → Queueable → Callout → External API

- Understand why asynchronous processing such as Queueable Apex is useful for external integrations.

- Use Named Credentials to keep endpoints and authentication configuration secure instead of hard-coding credentials.

- Distinguish between authentication and authorisation.

- Understand the purpose of Auth Providers in Salesforce integrations.

- Understand how Salesforce Connect and External Objects provide access to external data.

- Compare copying external data into Salesforce with accessing data directly from an external system.

- Compare point-to-point integration with middleware-based integration.

- Decide when an integration should be synchronous or asynchronous based on business requirements.

- Design an external recruitment integration for the Student Placement Management System.

- Design and document an API contract containing endpoints, request formats, responses, and errors.

- Implement proper integration error handling for failures such as:
  - 400 Bad Request
  - 401 Authentication Failure
  - 403 Forbidden
  - 500 Server Error

- Design retry strategies for temporary external-system failures.

- Understand idempotency and prevent duplicate processing during retries.

- Track integration status such as:
  - Pending
  - Sent
  - Failed
  - Retry Required

- Apply security principles by keeping credentials, tokens, passwords, and secrets outside Apex code.

- Design integrations that are reliable, maintainable, secure, and scalable.

- Explain Salesforce integration architecture confidently during technical interviews.

## ⭐ Key Outcome

The main outcome of this sprint is the ability to move from:

Salesforce-only Applications

to:

Salesforce ↔ External Systems

while maintaining **security, reliability, error handling, performance, and clean architecture**.
